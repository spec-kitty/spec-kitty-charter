## R2. Dependency and supply chain

**Decision.** `com.networknt:json-schema-validator:3.0.8` in `adapter-out-yaml` only:

```kotlin
implementation(platform(catalog.lib("spring-boot-bom")))
implementation(catalog.lib("json-schema-validator")) {
    exclude(group = "tools.jackson.dataformat", module = "jackson-dataformat-yaml")
    exclude(group = "tools.jackson.core")
    exclude(group = "org.slf4j", module = "slf4j-api")
}
implementation(catalog.lib("jackson-databind"))   // version from the Boot BOM: 3.1.5
implementation(catalog.lib("slf4j-api"))          // version from the Boot BOM: 2.0.18
```

**Rationale.**
- **3.x targets Jackson 3**, which the service already runs. 2.x would add a second JSON stack
  (Jackson 2).
- **A plain add moves the service to Jackson 3.2.1.** Gradle's conflict resolution would raise
  `jackson-databind` and `jackson-core` from 3.1.5 to 3.2.1 service-wide. `dependencyInsight` in a
  scratch copy showed "between versions 3.2.1 and 3.1.5". The exclusions keep Boot's tested
  version.
- **networknt 3.0.8 runs on Jackson 3.1.5.** The API probes were compiled and run against 3.1.5
  jars.
- **`jackson-dataformat-yaml` is unused.** It is only reached through `InputFormat.YAML`, and the
  adapter converts with `JsonMapper.valueToTree`.

**Alternatives considered.**
- networknt 2.x (Jackson 2): rejected, because it adds a second JSON stack.
- Accepting 3.2.1: rejected, because the service would then run a Jackson minor that Boot 4.1.1
  was not built against.
- A hand-written validator: rejected by ADR-0017 D3.

**API, verified in scratch against the jar.**
- `SchemaRegistry.withDefaultDialect(Dialect, Consumer<Builder>)`.
- `Dialect.builder(Dialects.getDraft202012()).unknownKeywordFactory(DisallowUnknownKeywordFactory.getInstance())`.
  An unknown keyword then throws `InvalidSchemaException` at schema load. The default factory
  silently ignores it.
- `Builder.schemaIdResolvers(r -> r.mapPrefix(..., "classpath:..."))`.
- With the default loader, nothing is fetched remotely: a `$ref` to `https://example.invalid/x.json`
  throws `FileNotFoundException`.
- `schema.validate(JsonNode)` returns a `List<com.networknt.schema.Error>`. Each error carries
  `getKeyword()`, `getInstanceLocation()`, `getEvaluationPath()`, `getSchemaLocation()`,
  `getMessageKey()`, `getArguments()` and `getProperty()`.
- The Draft 2020-12 metaschema and its vocabularies are bundled in the jar.

**Binary compatibility (plan squad).** All 408 external constant-pool references of the 315
networknt classes were checked. The 123 that point at `tools/jackson/*` or `com/fasterxml/*`
resolve against jackson-core and databind 3.1.5 plus jackson-annotations 2.21, by name and full
descriptor, with 0 missing. So the exclusion links no Jackson 3.2-only API.

**slf4j.** Without the exclusion, networknt's pom raises the service's `slf4j-api` from 2.0.18 to

regex. The generated patterns use only constructs that ECMA-262 and Java both support.

## R4. URN grammar and the node-kind vocabulary

- **Patterns.** Generated, not hand-written. The ECMA-262-portable class is `[A-Za-z0-9_/.-]`,
  with the dash last.
  - Any URN: `^(directive|tactic|styleguide|toolguide|paradigm|procedure|agent_profile|mission_step_contract|glossary_pack|skill|anti_pattern|asset|template|action|mission_type):[A-Za-z0-9_/.-]+$`.
  - Shard node prefix equals kind: `allOf` over 15 branches, each
    `if {kind: const K} then {urn: pattern ^K:}`. Draft 2020-12 has no `$data`.
  - Fragment node id: `^[A-Za-z0-9_/.-]+$`. This matches core's merge-time `malformed_urn` rule.
- **Java versus core.** Java's `Urn.parse` accepts any non-empty id. The schema tightens it to
  core's character class. On open-packs, 358 shard nodes conform with 0 violations.
- **Fragment node kinds (R14).** One name per concept:
  - the 13 artifact-kind plurals the service models: `directives`, `tactics`, `styleguides`,
    `toolguides`, `paradigms`, `procedures`, `agent_profiles`, `mission_step_contracts`,
    `glossary_packs`, `skills`, `anti_patterns`, `assets` and `templates`;
  - plus `mission_types` and `actions`.

  Core's `mission_steps` and `mission_type` are refused. `mission_step_contracts` is in core's
  accepted set, so authors who use it stay valid for core. `actions` and `anti_patterns` are
  refused by core and accepted here; this is recorded.

## R5. Findings shape and the #115 mapping

- **Core's output.** `charter pack validate --json` returns `{ok, errors[], advisories[]}`. Each
  item carries `severity` (`error` or `advisory`), `artifact_type`, `artifact_id`, `file`
  (absolute), `message` and an optional `category`. There is no place-in-file field.
- **Duplicates.** Core reports an unknown `pack.yaml` key twice, as `drg` and as `pack`.
- **Fail-fast.** Core aborts the fragment load on an invalid `pack.yaml`, so planted endpoint
  defects go unreported (the planted `all3u` case).
- **`doctor charter-packs --json`.** It needs a project. A scratch git repo with only
  `.kittify/config.yaml` works.

The mapping table is in [contracts/pack-finding-codes.md](contracts/pack-finding-codes.md#core-mapping).

## R7. The charter build's seams

- **Contracts module.** It has no JSON Schema library. `checkPackSchemas` follows the closure
  checker's pattern: Java in `contracts/src`, `javaexec`, and a report in `build/reports/`. It
  uses snakeyaml only, so no new dependency, and is wired into `check`.
- **Release gate.** No `contract-charter-v*` tag exists, so `checkContractCompatibility` has no
  baseline. Empirically, oasdiff flags a `DiagnosticCode` value addition as
  `response-property-enum-value-added` (breaking) and passes a reworded description (risk K3).
- **Scenarios.** They run through `CharterContractSuite`, with fixtures written by
  `ScenarioPacks`. A new code must enter the contract enum first, or `ContractConformance` fails.
- **ArchUnit.** `RefusalHandler$1` reads `RefusalCode.PACK_LEVEL_MISMATCH` with `getstatic`
  (javap), so the rule exempts `..rest..`.
- **Round-trip on open-packs `main`.** Only three things fail: the `built-in` presence check, the
  walk roots, and the `internal` diagnostics row. This was shown by an overlay experiment: 520
  tests, 1 failure.
- **Vendored packs.** They were vendored by hand and carry `PROVENANCE.md`. No code reads them by
  path; only `.kittify/config.yaml` does.
- **PIT.** No threshold exists, and it runs nightly only. It can be targeted per class with an
  init script (4.8 s for two classes).
