# Reader persona: Non-engineer developer

| Field | Value |
|---|---|
| **Group** | outside this repository, adopts what it produces |
| **Actor type** | human |
| **Primary goal** | Build with agents and trust that good practice is applied for them. |

## What this reader needs

- What the charter does for them in everyday terms: it gives every agent the same agreed
  rules, so quality does not depend on what they remembered to ask for.
- Which defaults they get without doing anything, and the one or two choices worth making.
- Jargon explained or linked to the [glossary](/glossary/).

## What frustrates them

- Pages that assume they know packs, schemas or the DRG.
- Errors that name internals instead of saying what to do next.

## Signal that the documentation served them

They can say in one sentence what the charter changes for their project, and know where to
turn a rule on or off.

## Where to start

Start with the [product](/context/product/). Skip the architecture and API sections.
