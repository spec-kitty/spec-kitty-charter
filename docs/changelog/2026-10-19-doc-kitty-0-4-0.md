# 2026-10-19 — The docsite moves to doc-kitty 0.4.0

The documentation site now builds with `@spec-kitty/doc-toolkit` `0.4.0` (was `0.2.0`), which
runs on Astro 7 and Starlight 0.42 and needs Node 22.22+. Pages read the same and are written
the same way; the change is in the toolkit, the build and a few reader-facing extras.

## What changed

- **New reader capabilities.** Every heading has a clickable anchor; diagrams and images open in a
  full-window view (Esc to close); draft pages carry a draft notice; the sidebar keeps the
  current page in view; and shared links get Slack/WhatsApp/LinkedIn preview cards.
- **OKF export.** Every build now writes an Open Knowledge Format bundle (`dist/okf/`), and CI
  checks it for conformance (`npm run check:okf`). An agent can consume the docs as structured
  data, not just HTML.
- **Gherkin fences.** A ```` ```gherkin ```` block renders as a structured scenario, with a
  warning on imperative steps. (Generated Specification pages from the Gherkin scenarios in
  `contracts/` are a separate, deferred step.)
- **Dates are UTC instants.** Every page's `updated` (and `stale_after`) is now
  `YYYY-MM-DDT00:00:00Z`, which doc-kitty 0.4.0 expects.
- **Glossary pages are generator-owned.** doc-kitty 0.4.0 writes `docs/glossary/**/README.md`
  with its own frontmatter and will not accept extra keys, so the build no longer post-processes
  them and the docs checks exempt a generated glossary page from the authored-only rules.

See [Building the docsite](/guides/docsite/) for the build steps and
[ADR-0003](/adr/0003-docs-follow-doc-kitty/) for the convention.
